## 2. Caída de producción del frontend (resuelta) — hallazgo nuevo

Durante los merges, la portada de producción daba **HTTP 500 en todo el SSR**. Diagnóstico
(systematic-debugging):

- **No la causaron los PR de B-03/B-04.** Empezó ~11 min antes, con el deploy del PR **#29**
  («fix(deps): CVE XSS de @tanstack», que subió `@tanstack/react-start`).
- **Causa raíz:** tras ese bump, npm hoistó al nivel superior un `@tanstack/router-core` **viejo**
  (1.171.13) que **no exporta `_getRenderedMatches`**, mientras `start-server-core` sí lo importa.
  El bundle SSR externaliza `router-core` → en runtime resolvía al viejo y reventaba el import ESM.
  El build pasaba porque cada paquete resolvía su `router-core` anidado.
- **Fix (PR #30, merged):** `overrides` de `@tanstack/router-core` a **1.171.37**, que dedupa todo
  el árbol a una versión con el export. No revierte el CVE de #29.
- **Verificado:** portada y `/buscar` → 200; 0 errores de runtime en el deploy nuevo.

Lección guardada en memoria (`tanstack-router-core-skew-ssr-2026-10`): con los `@tanstack/*` en
rangos `^`/`~`, un redeploy puede re-resolver a una combinación rota; **una portada 200 no garantiza
que el SSR esté sano**.
